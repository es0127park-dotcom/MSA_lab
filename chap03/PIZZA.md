# 🍕 MSA 요청 처리 방식 3가지 (피자집 비유)

피자 주문이 들어왔을 때, **도우(Dough) MS ➡️ 토핑(Topping) MS ➡️ 화덕(Oven) MS**가 어떻게 협력하여 피자를 완성하는지에 대한 3가지 패턴입니다.

## 1️⃣ 동기적 요청 (Synchronous Call)

**= "블락 당함 (Blocked): 앞 조리대가 끝나야만 다음으로 넘어가는 직렬 구조"**

- **상황:** 피자 요청이 들어오면 모든 조리대가 한 줄로 서서 순서대로만 작업합니다.
- **동작 흐름 (필기 기준):**
  1. **피자 요청** ➡️ **도우 MS** 호출
  2. 도우 MS가 끝날 때까지 토핑, 화덕은 아무것도 못 하고 대기 (**블락 당함**)
  3. 도우 완료 ➡️ **토핑 MS** 호출 (마찬가지로 화덕은 대기)
  4. 토핑 완료 ➡️ **화덕 MS** 호출
- **특징 요약:** 흐름이 가장 직관적이지만, 도우 조리대에서 문제가 생기면 뒤에 있는 토핑, 화덕 조리대는 끝없이 기다려야 하는 병목 현상(블락)이 발생합니다.

## 2️⃣ Saga 크레오그래피 패턴 (Choreography)

**= "출판(Publish)과 구독(Subscribe) 기반의 알아서 움직이는 조리대"**

- **상황:** 중앙 매니저 없이, 각 조리대가 **알림(이벤트)**을 듣고 자기 할 일을 알아서 시작합니다.
- **동작 흐름 (필기 기준):**
  1. **피자 요청**이 들어옴.
  2. **도우 MS:** 도우를 완성하면 **"도우완성(1)"** 이벤트를 허공에 외침 (**출판/Publish**).
  3. **토핑 MS:** 평소에 도우완성 알림을 듣기로 설정해둠 (**구독/Subscribe**). 알림을 듣자마자 토핑 작업을 시작하고 끝나면 **"토핑완성(1)"** 이벤트를 허공에 외침 (**출판**).
  4. **화덕 MS:** 토핑완성 알림을 듣고(**구독**) 알아서 화덕에 피자를 굽기 시작함.
- **특징 요약:** 각 조리대가 서로 명령을 내리지 않아 결합도가 낮습니다. 하지만 필기에 적어주신 것처럼 **"비즈니스(공정)가 바뀌면 복잡해지고 개판이 될 수 있음"**. (예: 도우 ➡️ 화덕 ➡️ 토핑 순서로 신메뉴가 나오면 알림 구독 설정을 다 뜯어고쳐야 함).

## 3️⃣ Saga 오케스트레이션 패턴 (Orchestration)

**= "중앙 매니저(오케스트레이터)의 Command(명령)와 Event(보고) 통제 시스템"**

- **상황:** 전체 흐름(UseCase)을 관리하는 **매니저**가 존재하며, 각 조리대는 매니저의 명령에만 움직이고 결과만 보고합니다.
- **핵심 개념 (필기 기준):**
  - **Command (명령):** 매니저가 해당 MS에게 "이거 해!"라고 지시하는 것.
  - **Event (보고):** 해당 MS가 매니저에게 "작업 완료했습니다!"라고 알리는 것.
- **동작 흐름 (필기 기준):**
  1. **피자 요청** ➡️ **매니저(오케스트레이션)**가 접수.
  2. 매니저 ➡️ **도우 MS**: "도우 생성해(1)" (**Command 출판**)
  3. 도우 MS ➡️ 매니저: "도우 완료" (**Event 구독/보고**)
  4. 매니저 ➡️ **토핑 MS**: "토핑 생성해(1)" (**Command 출판**)
  5. 토핑 MS ➡️ 매니저: "토핑 완료" (**Event 구독/보고**)
  6. 매니저 ➡️ **화덕 MS**: "화덕 구워(1)" (**Command 출판**)
- **특징 요약:** \* 필기에 적어주신 **"하나의 UseCase가 흘러가야 할 워크플로우 관리 (이건 동기적!)"**라는 말이 핵심입니다. 매니저가 순서를 꽉 잡고 있어서 흐름 파악이 매우 쉽습니다.
  - **"다른 피자 요청 받을 수 있음! 워크플로우가 하나 더 생기는 것!"**: 매니저가 능력이 좋아서 1번 피자 워크플로우를 진행하면서 동시에 2번 피자 워크플로우를 새로 생성해 병렬로 통제할 수 있습니다.

---

## 🔥 **필기 기반 최종 요약**

- **동기적:** 한 줄 기차. 앞 조리대 막히면 다 막힘 (**블락 당함**).
- **크레오그래피:** 각자도생. 서로 **출판/구독**하며 알아서 일함 (공정 바뀌면 **개판됨**).
- **오케스트레이션:** 매니저 지휘. 매니저가 **Command(명령)**를 내리고 MS가 **Event(완료 보고)**를 하는 통제 구조.
